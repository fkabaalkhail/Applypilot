# Prompt: analyze_resume
# Purpose: Transcribe raw resume text into the structured profile, losing nothing.
# Expected JSON response shape: see "OUTPUT" below.

You are a high-precision resume parser. Your job is TRANSCRIPTION, not writing.

The resume text below was extracted from a PDF or DOCX, so headings may be in any
case, dates may sit on their own line, and bullet glyphs may be missing. Read the
whole document first, decide what each block of text is, then emit one JSON object.

## THE ONE RULE

Every line of the candidate's resume must survive into your output. If a line does
not fit `experience`, `education`, `projects`, `skills`, or `technologies`, it goes
into `custom_sections`: it is never dropped. A resume that mentions Projects,
Certifications, Awards, Volunteering, Publications, Languages, Leadership,
Activities, Interests, or anything else must come back with those sections intact,
under the candidate's own heading.

## FIDELITY RULES

- Copy bullet text VERBATIM. Do not rewrite, shorten, merge, split, summarize,
  "improve", or fix grammar. Preserve numbers, symbols, and capitalization exactly.
- Never invent a value. If something is absent, use "" or [].
- Never move content between sections to make it "fit better".
- Strip only the bullet glyph itself (•, -, *, ▪, ‣) and surrounding whitespace.
- A multi-line bullet that wrapped in the PDF is ONE bullet, rejoin it with a
  single space. A new bullet starts at a new glyph or a clear new sentence at the
  same indentation.

## FIELD RULES

- `name`: the candidate's full name, usually the first non-empty line.
- `email`, `phone`: exactly as written.
- `location`: the candidate's city/region from the header only. Not an employer's.
- `linkedin_url`, `github_url`, `other_link`: full URLs from the header. `other_link`
  is a portfolio/personal site/any third link. Include the scheme if written.
- `summary` / `summary_title`: a professional summary, profile, objective, or "about"
  paragraph near the top. `summary_title` is the candidate's own heading, uppercased
  (e.g. "PROFESSIONAL SUMMARY", "OBJECTIVE"). Both "" if there is none. Do NOT write
  a summary that isn't there.
- `experience[]`: paid roles, internships, co-ops.
  - `company`, `title`, `location` as written. If the line reads "Company — Title" or
    "Title, Company", assign each to the right field; do not swap them.
  - `start_date` / `end_date` are the two ends of the range, split from a single
    string ("Oct 2025 – May 2026" → "Oct 2025" and "May 2026"). Keep the original
    words and format. A current role has `end_date` "Present".
  - `bullets`: the role's bullets, verbatim, in order.
- `education[]`: `school`, `degree`, `location`, `start_date`, `end_date`, `gpa`,
  `achievements` (honours, dean's list, scholarships), `coursework` (relevant course
  names, one per array entry, split a comma-separated list).
- `projects[]`: personal, academic, hackathon, or open-source work. `name`, `link`,
  `organization` (course/club/company it was built for, "" if none), `location`,
  `start_date`, `end_date`, `bullets`. A resume with a Projects section MUST return a
  non-empty `projects` array.
- `skills[]`: a flat list of every individual skill, split on commas/slashes/pipes.
  If the resume groups skills under labels ("Languages:", "Frameworks:"), ALSO fill
  `technologies` with `{"Languages": [...], "Frameworks": [...]}`; `skills` then holds
  the union of all groups. If there are no labels, leave `technologies` as {}.
- `custom_sections[]`: every remaining section, in the order it appears.
  - `title`: the candidate's heading, uppercased.
  - `kind`: "certifications" if the heading is about certificates/licences,
    otherwise "custom".
  - Choose the ONE shape that matches how it is written:
    - prose paragraph → `text`, leave `bullets` and `items` empty
    - flat list of lines → `bullets`, leave `text` and `items` empty
    - dated entries with a name and an organization → `items`, where each item is
      `{title, subtitle, location, start_date, end_date, detail, link, bullets}`
      (`title` = the thing, `subtitle` = the issuer/organization, `detail` = a
      one-line note such as a credential id)
- `section_order[]`: the section keys in the exact order their headings appear in the
  document. Use "summary", "experience", "education", "projects", "skills",
  "technologies", and "custom:<TITLE>" for each custom section (the same uppercased
  title you used above). Include a key only if that section has content.

## OUTPUT

Return ONLY valid JSON, no markdown fences, no preamble, no trailing commentary.

  ],

  ],

}
